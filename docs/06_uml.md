# UML
## Диаграмма вариантов использования (Use Case)
<img width="2340" height="4416" alt="image" src="https://github.com/user-attachments/assets/d1280fe4-05ae-4470-87be-a79375b97473" />
Диаграмма вариантов использования описывает функции системы DLP Tracker с точки зрения взаимодействия пользователей с веб-приложением. Выделены два актёра: Пользователь и Администратор, при этом Администратор является частным случаем Пользователя (наследует все его возможности) и дополнительно имеет права администрирования.

Пользователь может выполнить вход и выход из системы, просматривать список локаций, просматривать визиты по выбранной локации, добавлять, редактировать и удалять визиты, а также получать статистику по локации. Администратор, помимо перечисленных действий, выполняет управление пользователями: создание, изменение и удаление учётных записей. В диаграмме управление пользователями представлено как один вариант использования, который включает (include) операции создания, изменения и удаления пользователя.

## Диаграмма классов (Class)
<img width="688" height="1296" alt="image" src="https://github.com/user-attachments/assets/fd44326d-71f9-4713-bdb0-0da583528b13" />

Классы отражают основные сущности предметной области: Location и Visit.
Visit связан с Location отношением «многие к одному»: одна локация содержит много визитов.
Поля соответствуют структуре таблиц PostgreSQL и данным, которые вводятся в формах.

## Диаграмма последовательностей (Sequence) — добавление визита
<img width="1996" height="2132" alt="image" src="https://github.com/user-attachments/assets/707bc717-0abf-496e-a3cc-22e861273a6b" />

Диаграмма показывает взаимодействие пользователя, веб-приложения Flask и базы данных PostgreSQL при добавлении визита.
После сохранения данных система выполняет INSERT, подтверждает транзакцию и возвращает обновлённую страницу визитов/аналитики.
